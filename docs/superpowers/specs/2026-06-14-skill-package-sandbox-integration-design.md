# Skill 包管理与 Sandbox 集成设计

## 背景

当前平台已经具备 Agent 配置、聊天上下文构建、sandbox 工具执行、附件对象存储、MCP 工具注册和 Tool Registry。Agent 的能力主要来自系统提示词、默认模型和可用工具，尚未有可复用的文件化 Skill 能力包。

下一阶段需要建设 Skill 库。管理员上传一个 Skill zip 包，系统保存原始包，交给 sandbox-service 在隔离环境中解包和校验。校验通过后，Skill 版本可以绑定到 Agent。用户聊天时，后端把绑定 Skill 的 `SKILL.md` 注入 system prompt，并把 Skill 文件同步到当前 sandbox 会话的 `/workspace/skills/{skillKey}`，让模型可以通过 sandbox 工具读取模板、示例、脚本和其他资源文件。

## 目标

- 支持管理员上传一个 zip 包导入一个 Skill。
- 支持大包导入，zip 上限默认 500MB，解压后总大小默认 1GB。
- 原始 zip 保存在对象存储，后端只保存元数据、状态、`SKILL.md` 内容和文件清单。
- sandbox-service 负责 zip 下载、解压、安全检查、结构校验和文件清单扫描。
- 支持 Skill 多版本，Agent 绑定具体 READY 版本。
- 聊天运行时把 `SKILL.md` 内容注入提示词，把 Skill 文件同步到 sandbox 工作区。
- 管理端支持 Skill 列表、上传、导入状态查看、版本详情、文件清单和 Agent 绑定。

## 非目标

- 首版不支持一个 zip 批量导入多个 Skill。
- 首版不支持在线编辑 zip 内文件。
- 首版不实现 Skill 运行验证任务和示例输入执行。
- 首版不实现 Skill 市场、评分、依赖解析或跨环境发布。
- 首版不解析 `SKILL.md` 的复杂 frontmatter 语义；只要求文件存在并作为主说明注入。
- 首版不把资源文件内容直接注入模型上下文。

## 方案选择

采用方案：原始 zip 存对象存储，sandbox-service 负责导入校验和运行时同步。

备选方案 A：Java 后端解压校验，聊天时逐文件写入 sandbox。实现看似直接，但 zip 安全、目录安全、二进制文件处理都会压到 Java 后端，且现有 sandbox 写文件接口主要面向文本内容，不适合大包资源同步。

备选方案 B：只管理 zip，不进入聊天运行时。交付轻，但 Skill 会停留在后台素材库，不能形成 Agent 实际能力。

推荐方案让 Java 后端保持鉴权、审计、对象存储、元数据和统一响应职责，sandbox-service 负责文件处理和隔离校验，边界与现有架构一致。

## Skill 包结构

一个 zip 只允许包含一个 Skill。有效结构为以下两种之一：

```text
SKILL.md
assets/
examples/
scripts/
```

或：

```text
my-skill/
  SKILL.md
  assets/
  examples/
  scripts/
```

规则：

- 根目录或唯一一级目录下必须存在 `SKILL.md`。
- 多个并列一级目录且无法唯一识别 Skill 根目录时导入失败。
- zip 内路径统一归一为 `/` 分隔的相对路径。
- 禁止绝对路径、空路径、`.`、`..`、符号链接、设备文件和其他非常规文件类型。
- 导入成功后，文件清单保存相对 Skill 根目录的路径。

## 大包限制

默认限制：

```text
zip 单包上限：500MB
解压后总大小上限：1GB
文件数上限：3000
目录深度上限：16
单文件上限：200MB
SKILL.md 上限：512KB
校验任务超时：10 分钟
预签名下载 URL 有效期：30 分钟
```

这些限制应放入配置，便于生产环境按部署资源调整。sandbox-service 必须流式下载和流式解压，不能把整个 zip 或大文件一次性读入内存。

## 数据模型

### `skill_package`

保存 Skill 主体。

```sql
CREATE TABLE skill_package (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    skill_key VARCHAR(128) NOT NULL,
    name VARCHAR(128) NOT NULL,
    description VARCHAR(512),
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    current_version_id BIGINT,
    created_by BIGINT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_by BIGINT,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_skill_package_key UNIQUE (skill_key)
);
```

### `skill_version`

保存每次 zip 导入生成的版本。

```sql
CREATE TABLE skill_version (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    package_id BIGINT NOT NULL,
    version_no INT NOT NULL,
    original_filename VARCHAR(256) NOT NULL,
    bucket_name VARCHAR(128) NOT NULL,
    object_key VARCHAR(512) NOT NULL,
    zip_sha256 VARCHAR(64),
    status VARCHAR(32) NOT NULL,
    root_dir VARCHAR(512),
    skill_md_path VARCHAR(512),
    skill_md_content TEXT,
    file_count INT NOT NULL DEFAULT 0,
    zip_size_bytes BIGINT NOT NULL DEFAULT 0,
    uncompressed_size_bytes BIGINT NOT NULL DEFAULT 0,
    error_message TEXT,
    validation_started_at TIMESTAMPTZ,
    validation_completed_at TIMESTAMPTZ,
    created_by BIGINT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_by BIGINT,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_skill_version_package FOREIGN KEY (package_id) REFERENCES skill_package (id),
    CONSTRAINT uk_skill_version_package_no UNIQUE (package_id, version_no)
);
```

版本状态：

```text
UPLOADED -> VALIDATING -> READY
                    -> FAILED
```

### `skill_file_manifest`

保存校验后的文件清单。

```sql
CREATE TABLE skill_file_manifest (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    version_id BIGINT NOT NULL,
    relative_path VARCHAR(1024) NOT NULL,
    directory BOOLEAN NOT NULL DEFAULT FALSE,
    size_bytes BIGINT NOT NULL DEFAULT 0,
    sha256 VARCHAR(64),
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_skill_file_version FOREIGN KEY (version_id) REFERENCES skill_version (id),
    CONSTRAINT uk_skill_file_version_path UNIQUE (version_id, relative_path)
);
```

### `agent_skill_binding`

保存 Agent 与 Skill 版本绑定。

```sql
CREATE TABLE agent_skill_binding (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    agent_id BIGINT NOT NULL,
    skill_id BIGINT NOT NULL,
    version_id BIGINT NOT NULL,
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    sort INT NOT NULL DEFAULT 0,
    created_by BIGINT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_by BIGINT,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_agent_skill_agent FOREIGN KEY (agent_id) REFERENCES agent_config (id),
    CONSTRAINT fk_agent_skill_package FOREIGN KEY (skill_id) REFERENCES skill_package (id),
    CONSTRAINT fk_agent_skill_version FOREIGN KEY (version_id) REFERENCES skill_version (id),
    CONSTRAINT uk_agent_skill_binding UNIQUE (agent_id, skill_id)
);
```

## 后端模块

新增 `agent-hub-skill` 模块。

职责：

- `SkillPackageService`：创建上传 URL、确认上传、触发校验、查询 Skill 列表。
- `SkillVersionService`：查询版本详情、文件清单、激活版本、启停 Skill。
- `AgentSkillBindingService`：维护 Agent 与 Skill 版本绑定。
- `SkillRuntimeService`：聊天前查询 Agent 绑定 Skill，生成提示词注入内容，并触发 sandbox 文件同步。
- `SandboxSkillClient`：调用 sandbox-service 的 Skill 校验和同步接口。

依赖：

```text
agent-hub-common
agent-hub-storage
agent-hub-agent
agent-hub-sandbox
```

## 管理端接口

所有接口沿用统一 `ApiResponse`。

```text
GET  /api/skills/packages
POST /api/skills/packages/upload-url
POST /api/skills/packages/{packageId}/confirm-upload
GET  /api/skills/packages/{packageId}/versions
GET  /api/skills/versions/{versionId}
GET  /api/skills/versions/{versionId}/files
PUT  /api/skills/packages/{packageId}
PUT  /api/skills/packages/{packageId}/enabled
POST /api/skills/packages/{packageId}/versions/{versionId}/activate

GET  /api/agents/{agentId}/skills
PUT  /api/agents/{agentId}/skills
```

上传流程：

```text
1. 管理端调用 upload-url。
2. 后端创建 skill_package 或新版本，状态为 UPLOADED，返回 MinIO 预签名上传 URL。
3. 管理端 PUT zip 到对象存储。
4. 管理端调用 confirm-upload。
5. 后端 stat 对象，校验文件名、contentType 和 zip 大小。
6. 版本状态置为 VALIDATING，后台线程调用 sandbox-service 校验。
7. 管理端轮询版本详情，直到 READY 或 FAILED。
```

权限建议：

```text
skill:package:list
skill:package:create
skill:package:update
skill:package:upload
skill:package:enable
skill:version:activate
skill:version:read
agent:skill:update
```

菜单建议：

```text
Agent 管理
  - Agent 列表
  - Skill 库
```

## Sandbox Service 协议

```text

```

### 聊天运行时同步请求

```json
{
  "sandboxSessionId": "sbx_123",
  "skills": [
    {
      "skillKey": "official-writing-style",
      "versionId": 18,
      "downloadUrl": "https://minio-presigned-url",
      "zipSha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
    }
  ],
  "targetRoot": "/workspace/skills"
}
```

同步规则：

- 解包到 `/workspace/skills/{skillKey}`。
- 如果 `.agenthub-version` 已记录相同 `versionId + zipSha256`，跳过重复解包。
- 每次解包前清理该 `skillKey` 目录。
- 解包完成写入 `.agenthub-version`。
- 禁止符号链接、绝对路径、`..`、设备文件、空路径和过深目录。

## 聊天运行时

聊天开始时，`ChatService` 通过 `SkillRuntimeService` 查询当前 Agent 的启用 Skill 绑定，只使用 `READY + enabled` 的版本。

运行时生成两类结果：

1. 提示词注入内容：Skill 名称、`skillKey`、sandbox 路径和 `SKILL.md` 内容。
2. 文件同步清单：传给 sandbox-service，把 zip 解包到当前会话工作区。

注入规则：

- Agent 原有 `systemPrompt` 在最前面。
- Skill 内容按绑定 `sort` 排序追加。
- 单个 Skill 注入 `SKILL.md` 最多 64KB。
- 所有 Skill 合计注入最多 128KB。
- 超出时截断并追加中文提示，说明完整内容和资源位于 `/workspace/skills/{skillKey}`。
- 只注入 `SKILL.md`，不注入 assets、examples、scripts 等资源文件。

推荐提示词格式：

```text
已绑定以下 Skill。每个 Skill 的完整文件位于 /workspace/skills/{skillKey}。
如需读取示例、模板、脚本或其他资源，请使用 sandbox 工具访问对应目录。

[Skill: official-writing-style]
名称：公文写作规范
路径：/workspace/skills/official-writing-style
SKILL.md:
当用户需要起草通知、请示、汇报和方案时，先确认文种、受众、语气和必须包含的事实，再输出结构清晰、措辞稳妥的中文正文。
```

如果当前 Agent 没有绑定 Skill，则不改变现有聊天行为。

如果 Skill 文件同步失败，本轮聊天中断并通过统一错误事件返回：`Skill 同步到沙箱失败：{原因}`。这样避免模型看到 Skill 提示词，却无法读取对应资源文件。

## 管理端页面

新增 `Skill 库` 页面：

- Skill 列表：名称、标识、启停状态、当前版本、最近导入状态、文件数、更新时间。
- 上传 Skill：选择 zip，展示上传进度，确认后进入校验状态。
- 版本详情：状态、错误信息、`SKILL.md` 预览、文件清单。
- 激活版本：把 READY 版本设为当前版本。
- 启停 Skill。

Agent 编辑页增强：

- 新增 `Skill 绑定` 区域。
- 可选择 READY Skill 版本。
- 支持排序、启停、移除绑定。
- 保存后写入 `agent_skill_binding`。

## 错误处理

导入阶段：

- zip 未上传成功：`上传失败，请重新上传 Skill 包`。
- 非 zip 或文件损坏：`Skill 包不是有效的 zip 文件`。
- 缺少 `SKILL.md`：`Skill 包缺少 SKILL.md`。
- 多个顶层目录且无法唯一识别：`Skill 包目录结构不符合规范`。
- 路径越界、绝对路径、`..`、符号链接：`Skill 包包含不安全路径`。
- 超过大小、文件数、深度限制：返回具体限制值。
- sandbox-service 不可用：版本标记 `FAILED`，错误为 `沙箱校验服务不可用`。

聊天阶段：

- Agent 绑定了不存在、禁用或未 READY 的 Skill：该绑定不注入，记录告警。
- 所有绑定都不可用：不注入 Skill，聊天继续。
- sandbox 同步失败：中断本轮聊天并返回统一错误。
- `SKILL.md` 超长：允许 READY，注入时截断。

## 安全边界

- 前端只访问 Java 后端，不直接访问 sandbox-service。
- 原始 zip 不通过 Java 内存转发给 sandbox-service，后端只传短期预签名下载 URL。
- sandbox-service 下载和解压必须使用临时目录，校验结束后清理临时目录。
- zip 解压必须做路径归一和目录边界检查。
- 禁止符号链接和非常规文件类型。
- zip 大小、解压总大小、文件数、目录深度、单文件大小都必须强制限制。
- 管理端只能展示 `SKILL.md` 和文件元数据，不直接暴露永久对象存储地址。
- 聊天运行时预签名 URL 有效期短，且只传给内部 sandbox-service。

## 测试计划

### 后端 Java

- 创建上传 URL：只允许 `.zip`，生成 `skill-packages` objectKey，版本状态为 `UPLOADED`。
- confirm-upload：对象大小、contentType、状态流转正确。
- 校验成功：写入 `skill_md_content` 和 `skill_file_manifest`。
- 校验失败：版本状态为 `FAILED`，错误消息可读。
- 激活版本：只能激活 READY 版本。
- Agent 绑定：只能绑定 READY 版本，排序和启停生效。
- SkillRuntimeService：按 Agent 查询启用 Skill，生成提示词注入内容。
- 注入长度限制：单 Skill 和总长度都能截断。
- ChatService：system prompt 包含 Skill 注入内容，并在流式调用前触发 sandbox 同步。

### sandbox-service

- 正常 zip：识别根目录和 `SKILL.md`。
- zip slip：拒绝 `../evil.txt`。
- 绝对路径：拒绝。
- 符号链接：拒绝。
- 空路径和非法路径：拒绝。
- 超大文件、超多文件、超深目录：拒绝。
- 大包校验：流式下载和解压，不把完整 zip 读入内存。
- sync-to-session：解包到 `/workspace/skills/{skillKey}`。
- 重复同步：同版本同 hash 跳过。

### 管理端

- Skill 列表、上传、导入状态轮询、版本详情、文件清单展示。
- 导入失败时展示中文错误原因。
- Agent 编辑页可以绑定 Skill、调整排序、启停绑定。
- `SKILL.md` 预览长内容时不撑破布局。

## 实施顺序

1. 扩展 sandbox-service：实现 Skill zip 校验和同步接口。
2. 新增 Java `agent-hub-skill` 模块、数据库迁移、实体、Mapper、Service。
3. 接入对象存储上传和异步校验任务。
4. 实现管理端 Skill 库页面和 Agent Skill 绑定入口。
5. 接入 ChatService 运行时注入和 sandbox 同步。
6. 补齐后端、sandbox-service、管理端测试。

## 验收标准

- 管理员可以上传一个大 zip Skill 包，并看到导入状态。
- 缺少 `SKILL.md`、路径不安全或超过限制的 zip 会被拒绝，并显示中文错误。
- READY 版本可以查看 `SKILL.md` 和文件清单。
- Agent 可以绑定指定 Skill 版本并调整排序。
- 用户使用绑定 Skill 的 Agent 聊天时，system prompt 包含 `SKILL.md` 内容。
- 同一轮聊天中，Skill 文件已同步到 `/workspace/skills/{skillKey}`。
- 模型可以通过 sandbox 工具读取 Skill 资源文件。
- 未绑定 Skill 的 Agent 聊天行为不回退。
