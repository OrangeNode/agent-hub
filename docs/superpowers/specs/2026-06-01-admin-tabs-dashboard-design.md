# 管理端多标签与工作台优化设计

## 1. 背景

当前 `admin-web` 已具备基础后台布局，但还有两类体验问题影响可用性与观感：

1. 多标签栏能力不足，只支持点击与关闭，不支持拖动排序，也缺少右键快捷操作。
2. 工作台页面信息结构过薄，视觉上更像占位页，不符合企业后台首页应有的稳定感与信息密度。

本次优化只聚焦 `admin-web`，不涉及后端接口变更。

## 2. 目标

本次交付目标如下：

- 多标签栏支持拖动排序
- `工作台` 标签固定在第一位且不可关闭
- 标签栏支持右键菜单，提供常用批量关闭能力
- 工作台页面重做为更符合企业后台风格的数据总览页
- 保持现有路由、鉴权、动态菜单逻辑不变

## 3. 范围

### 3.1 包含

- 标签状态管理增强
- 标签拖拽排序交互
- 标签右键菜单交互
- 工作台页面布局和样式重做
- 与上述行为相关的前端测试

### 3.2 不包含

- 后端接口改动
- 新增业务模块页面
- 标签持久化到服务端
- 工作台接入新的统计接口

## 4. 设计方案

### 4.1 多标签行为

标签系统遵循以下规则：

- `工作台` 永远存在，路由固定为 `/dashboard`
- `工作台` 永远位于标签列表第一位
- `工作台` 不允许关闭
- `工作台` 不允许被拖动到其他位置
- 其他标签允许在非工作台区域内自由拖动排序

右键菜单支持以下操作：

- 关闭当前
- 关闭其他
- 关闭右侧
- 关闭全部

补充规则：

- 对 `工作台` 右键时，不提供“关闭当前”
- “关闭全部”执行后仅保留 `工作台`
- “关闭其他”在当前标签为 `工作台` 时，效果等同于保留 `工作台`、关闭其他全部标签
- 批量关闭后如果当前激活标签被移除，则自动回退到合理标签；如果没有其他标签则回到 `工作台`

### 4.2 拖拽交互

采用原生拖拽实现，不引入额外依赖。

交互约束：

- 仅非 `工作台` 标签支持拖拽
- 拖拽悬停目标为非 `工作台` 标签时执行位置交换
- 任何拖拽结果都必须保证 `工作台` 仍在索引 0
- 拖拽过程中保持当前激活标签不丢失

### 4.3 标签状态层

标签相关能力统一收敛到 `tabs store`，布局层只负责展示和事件转发。

状态层新增职责：

- 保证默认存在 `工作台`
- 保证 `工作台` 固定在第一位
- 提供拖动排序方法
- 提供关闭当前、关闭其他、关闭右侧、关闭全部方法
- 在批量关闭后返回正确的目标路由

### 4.4 工作台页面

工作台重做为更偏企业后台的“数据总览型”首页，结构如下：

1. 顶部欢迎区
   - 欢迎语
   - 当前登录账号
   - 当前角色信息
   - 辅助状态信息

2. 核心指标区
   - 角色数
   - 可见菜单数
   - 权限点数
   - 当前活跃标签数

3. 快捷入口区
   - 用户管理
   - 角色管理
   - 菜单管理

4. 当前账号概览区
   - 当前账号角色列表
   - 当前可访问模块
   - 使用说明性摘要

视觉要求：

- 保持后台风格，克制、清晰、信息密度适中
- 不使用营销式大卡片或夸张 Hero
- 各信息区块尺寸稳定，避免移动端和窄屏下错位
- 继续沿用当前配色体系，但提升层级、留白和比例

## 5. 影响文件

主要影响以下文件：

- `admin-web/src/stores/tabs.ts`
- `admin-web/src/stores/tabs.helpers.ts`
- `admin-web/src/layouts/AdminLayout.vue`
- `admin-web/src/views/DashboardView.vue`
- `admin-web/tests/tabs.spec.ts`
- 视情况新增与标签交互相关的测试文件

## 6. 测试策略

本次至少覆盖以下验证点：

- 打开新标签后 `工作台` 仍在第一位
- 关闭行为不会移除 `工作台`
- 关闭右侧、关闭其他、关闭全部行为符合预期
- 拖动排序不会把 `工作台` 移出第一位
- 工作台页面可正常构建渲染

## 7. 风险与约束

- 原生拖拽需要仔细处理索引与激活态，避免拖动后标签状态错乱
- 右键菜单需要避免与已有点击关闭事件冲突
- 工作台页面改造只使用现有数据源，不能依赖新的后端统计接口

## 8. 交付结果

完成后，管理端应具备更接近成熟后台系统的标签栏体验，并且工作台首页在布局、留白、信息组织和视觉重心上明显优于当前版本。
